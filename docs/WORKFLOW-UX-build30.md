# Картка об'єкта: спрощення восьми етапів, build 30

Локальна версія: http://127.0.0.1:4174/?build=30. Публікація не виконувалась.

| Етап | Основний вміст |
|---|---|
| Лід | Контакти, адреса, тип об'єкта та побажання клієнта. Без технічної специфікації, стрінгів і фінансових звітів. |
| Замір | Задачі виїзду з CRM, їх фактичні дати, виконавці, результати, фото заміру й моделі/схеми. Дата монтажу не підміняє дату заміру. |
| КП | Позиції, ціни, монтаж, загальна сума, файли КП. Додавання обладнання та зміна сум згорнуті. |
| Договір | Реквізити, сума договору, отримано/залишок, тільки платежі клієнта, договір і чеки. Внутрішні витрати та кошторис — у згорнутому блоці власника/адміністратора. |
| Монтаж | Робочий чекліст, план/видано/використано, фото монтажу. Виконані групи чекліста згорнуті; технічні дані, серійники та MPPT відкриваються за потреби. План із КП переноситься тут. |
| Перевірка | Незмінюваний підсумок чекліста й монтажні фото; для виправлення позначок потрібно повернутися до монтажу. |
| Паспорт | Перегляд/друк паспорта та файли паспорта/акта. У фотографіях паспорта немає чеків, договорів, фото заміру, сервісу й окремих серійних табличок. |
| Сервіс | Сервісні CRM-задачі, звіти та фото сервісу. Увесь старий вміст залишається у згорнутому архіві. |

Форми додавання документів/фото та обладнання згорнуті. Архівна розмітка створюється тільки після відкриття архіву, зображення мають відкладене завантаження. Це зменшення початкового вмісту екрана, не виміряна гарантія швидкості.

Збережені колекції не фільтруються й не очищаються. Видимі файли/фото зберігають оригінальні індекси для правильного відкриття та видалення. Фото чека не дублюється у договорі, якщо вже є файл з тим самим непорожнім ID платежу й назвою. Інші варіанти залишаються видимими; повний архів нічого не відкидає.

Нові CRM-фото отримують категорію заміру, сервісу або документа, щоб не потрапляти у монтаж/паспорт. Реквізити договору зберігаються у наявному JSON фінансів з підтримкою старих локальних полів. Це перевірено модельним round-trip без запитів до Supabase.

Перевірено: 75 автоматичних тестів; усі 8 етапів у браузері; монтаж і незмінюваний перегляд об'єкта на 50%; відкриття повного архіву (6 файлів, 7 фото й історія); початкові значення форм оплати/сервісної задачі без збереження нових операцій. Навігація не змінює поточний статус. Сума/залишки та збережені вкладення не очищались.

Це аудит етапів картки об'єкта, не повторна перевірка всіх глобальних сторінок, прав доступу або онлайн-синхронізації. Існуючі обмеження клієнтського порталу й інтеграцій цим оновленням не оголошуються виправленими.
