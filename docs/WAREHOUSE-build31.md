# Локальний склад — build 31

Дата: 24.10.2026. Тільки localhost; публічний Vercel та Supabase не змінювалися.

## Що можна спробувати

- Три вкладки: залишки, документи руху, каталог обладнання.
- Спільний пошук за словами назви, артикулом, брендом, моделлю, штрихкодом і отриманими серійними номерами; категорії та фільтри наявності/бренду.
- Картка товару без прямого редагування кількості; структуровані характеристики за напрямком. Порожній артикул генерується автоматично.
- Прихід з кількома рядками, закупівельною ціною, витратами на одиницю, серійними номерами та локальними вкладеннями. Чернетка не змінює залишків; повторне проведення заблоковане.
- Резерв під об’єкт; зняття резерву; видача з погашенням власного резерву й захистом чужого.
- Видача не означає монтаж. Використання та повернення невикористаного оформлюються окремо.
- Інвентаризація з фактичною кількістю, причиною та історією різниці.
- Старі рухи показуються без руйнівної міграції. «Попередній вигляд» дозволяє порівняти інтерфейси на тій самій базі.

## Фінансові правила

Собівартість залишку при приході усереднюється за кількістю. Раніше видані матеріали зберігають свою зафіксовану собівартість. Повернення невикористаного обладнання відбувається за історичною собівартістю видачі. Прихід, резерв, видача і використання не створюють автоматичної оплати в касі.

## Зберігання і відновлення

Ключі використовують наявний ізольований префікс `sparta.local.v1.`. Канонічний складський пакет: `solarObjectManager.warehouseWorkspace.v31`. Для сумісності з іншими розділами зберігаються дзеркала старих ключів товарів і рухів.

Перед записом операції створюється `solarObjectManager.warehouseTransaction.v31`: він дозволяє відновити спільний запис складу й матеріалів об’єкта після помилки/переривання. Нові операції блокуються, поки попередній запис не завершено. На доступних браузерах зміни складу серіалізуються через Web Locks. Старі форми не є окремою транзакційною системою.

Незмінний знімок даних до першого запуску нового складу: `solarObjectManager.warehouseBackup.before31`. Початкові файли об’єктів залишаються у тому самому локальному IndexedDB; вкладення складу використовують цей самий механізм з окремими ключами.

## Межі першої версії

Один основний склад, без повноцінних міжскладських переміщень і адресного WMS. Багаторядкові прихід та інвентаризація; видача/резерв/повернення/використання наразі по одній позиції. Серійні номери фіксуються при отриманні, але індивідуальний вибір екземпляра при видачі — наступний етап. Імпорт таблиць, комплектування, облік пошкоджень і спільна онлайн-робота потребують подальшої реалізації. Ролі та локальний перемикач режимів не замінюють серверну авторизацію; до узгодження backend-схеми цей модуль не публікувати.
